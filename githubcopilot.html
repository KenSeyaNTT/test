配布用 / 2026.09

VS CODE · CHAT / AGENT

Allow確認を、
必要な分だけ減らす

VS CodeのチャットやAgentが実行する端末コマンドを、確認なしで進められるように設定します。対象はチームで決めた安全なコマンドだけに絞ります。

結論

設定JSONに主に2つの項目を追加し、VS Codeを再読み込みします。今回の確認用コマンドは Write-Output です。

まずは1分で設定

ユーザー設定に追加する方法です。すでに同じ項目がある場合は、値を置き換えず内容を統合してください。

1

設定JSONを開く

Ctrl + Shift + P を押し、「Preferences: Open User Settings (JSON)」を選択します。

2

下の設定を追加

右上の「コピー」ボタンで設定をコピーし、JSONの末尾に追加します。既存の最後の項目にはカンマを付けます。

3

動作を確認

VS Codeのチャットで Write-Output "allow test" を実行し、Allow確認が出ないことを確認します。

settings.json / 推奨の最小設定 
{
  "chat.tools.terminal.enableAutoApprove": true,
  "chat.tools.terminal.autoApprove": {
    "/^(Write-Output|echo)( .*)?$/": true,
    "/^git (status|diff|log)( .*)?$/": true,
    "/^(npm|pnpm|yarn) (test|run test)( .*)?$/": true,
    "rm": false,
    "rmdir": false,
    "del": false,
    "Remove-Item": false,
    "curl": false,
    "wget": false
  },
  "chat.tools.global.autoApprove": false
}

この例では、出力・Gitの参照系コマンド・テスト実行だけを自動承認します。削除系や外部通信系は明示的に拒否します。

!

大事な注意: chat.tools.global.autoApprove を true にすると、端末以外のツールも含めて確認が減りすぎる可能性があります。全員配布では false のままにしてください。

設定の意味

Allow確認は、VS Codeがコマンドの内容を確認するための安全装置です。消す範囲を分けて考えます。

自動承認してよい例

  • Write-Output / echo など、画面に文字を出すだけの処理
  • git status / git diff / git log など、参照だけのGit操作
  • npm test など、チームで内容を把握しているテスト

確認を残す例

  • ファイルの削除・移動・上書き、設定変更
  • curl / wget など、外部から取得する処理
  • 管理者権限、認証情報、ネットワーク、Docker操作

みんなに展開する方法

配布対象と適用範囲に合わせて、次のいずれかを選びます。

個人設定として配布

このHTMLを共有し、各自がUser Settings (JSON)へ追加します。最初の検証に向いています。

リポジトリ単位で配布

プロジェクトの .vscode/settings.json に設定します。そのリポジトリを開いた時だけ有効です。

管理端末へ一括配布

Intuneや社内端末管理の設定配布を使う場合は、対象コマンドのAllowlistをレビューしてから適用します。

!

ワークスペース設定をコミットする場合は、秘密情報を扱う作業や本番運用のリポジトリへ同じAllowlistをそのまま適用しないでください。プロジェクトごとに必要なコマンドを見直します。

配布前チェック

設定を配る前に、代表端末で「減った確認」と「残す確認」の両方を試します。

  • VS CodeのバージョンとCopilot Chatが全員ほぼ同じ
  • 設定JSONの既存項目を消していない
  • Write-Output "allow test" で確認が出ない
  • Remove-Item など危険な操作では確認が残る
  • JSONのカンマ・波括弧にエラーがない
  • 業務上不要なコマンドをAllowlistに入れていない

うまくいかないとき

確認が出ること自体が、設定の失敗とは限りません。

設定したのにAllow確認が出る

実行された文字列がAllowlistの正規表現と一致しているか確認します。コマンドの前後にオプションや別のコマンドが付くと一致しないことがあります。また、削除・外部通信・権限変更の確認は残す設計です。

設定JSONに赤い波線が出る

JSONの末尾カンマ、引用符、波括弧を確認します。既存の設定ファイルがJSONCの場合でも、今回のブロックは通常のJSON形式で追加できます。

チームの端末だけ動作が違う

VS Codeのバージョン、Copilot Chatの状態、ユーザー設定とワークスペース設定の優先順位を確認します。会社のポリシーで設定が上書きされている場合は、端末管理側の担当者に確認してください。
